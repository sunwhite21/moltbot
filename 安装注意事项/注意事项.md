## 2. pnpm 安装问题

### 问题
执行 `npm install -g pnpm` 时出现 `zsh: command not found: npm install -g pnpm`

### 原因
在 Trae IDE 的终端环境中，npm 命令需要先加载 nvm (Node Version Manager) 的初始化脚本才能正常工作。

### 解决方案
```bash
# 先加载 nvm 环境，再执行安装
source ~/.nvm/nvm.sh && npm install -g pnpm

# 验证安装
pnpm -v
```

### 注意事项
所有需要使用 npm/pnpm 的命令，都需要先执行 `source ~/.nvm/nvm.sh`，或者在命令前加上该前缀。

## 5. 执行 onboard 命令

### 问题
执行 `pnpm clawdbot onboard --install-daemon` 时命令无法识别。

### 原因
在 pnpm workspace 中，需要使用 `pnpm exec` 或直接运行入口文件。

### 解决方案
```bash
# 方式 1：直接运行入口文件
source ~/.nvm/nvm.sh && node moltbot.mjs onboard --install-daemon

# 方式 2：使用 pnpm exec
source ~/.nvm/nvm.sh && pnpm exec clawdbot onboard --install-daemon
```

### 注意事项
- `onboard` 命令会进入交互式向导模式
- 如果需要非交互式安装守护进程，可以使用其他命令

## 6. Telegram User ID 获取方法

### 获取方式

#### 方法 1：最安全（推荐）
给您的机器人发消息，然后运行：
```bash
pnpm moltbot logs --follow
```
从日志中读取 `from.id` 字段。

#### 方法 2：使用 Telegram API
调用 API：
```
https://api.telegram.org/bot<bot_token>/getUpdates
```
从返回的消息中读取 `message.from.id`。

#### 方法 3：使用第三方机器人
- 私信 `@userinfobot`
- 或私信 `@getidsbot`

### 为什么需要 User ID？
- 识别您是管理员/授权用户
- 防止陌生人随意使用机器人
- 配合 `allowFrom` 参数控制访问权限

## 7. "Accounts Unsupported schema node. Use Raw mode" 错误

### 问题
在 UI 配置界面中，`accounts` 字段显示错误：`Unsupported schema node. Use Raw mode.`

### 原因
`accounts` 字段的 JSON Schema 结构过于复杂（使用 `additionalProperties` 定义复杂对象），UI 表单编辑器无法提供合适的可视化编辑界面。

### Schema 结构
```typescript
accounts: z.record(z.string(), TelegramAccountSchema.optional()).optional()
```

### 解决方案

#### 方式 1：使用 Raw Mode
在配置界面切换到 "Raw mode"，直接编辑 JSON 格式的配置。

#### 方式 2：使用 CLI 命令
```bash
# 添加 Telegram 账户
pnpm moltbot channels add telegram --account <account-id>
```

#### 方式 3：直接编辑配置文件
```bash
nano ~/.clawdbot/moltbot.json
```

### 相关文件
- UI 表单分析：`ui/src/ui/views/config-form.analyze.ts`
- UI 表单渲染：`ui/src/ui/views/config-form.node.ts`
- Schema 定义：`src/config/zod-schema.providers-core.ts`

## 9. Node 版本问题

### 问题
```
WARN Unsupported engine: wanted: {"node":">=22.12.0"} (current: {"node":"v16.20.2"})
```

### 原因
当前终端使用的 Node 版本是 v16.20.2，但项目要求 >=22.12.0。

### 解决方案
```bash
# 查看已安装的 Node 版本
nvm list

# 切换到 Node 22
nvm use 22

# 如果没有安装，先安装
nvm install 22
nvm use 22

# 设置为默认版本
nvm alias default 22

# 验证版本
node -v
```

### 注意事项
- Gateway 服务使用 Node 22.22.0
- 确保当前终端也使用相同版本
- 项目要求：Node >=22.12.0

## 10. NODE_OPTIONS 错误

### 问题
```
/Users/freethinker/.nvm/versions/node/v16.20.2/bin/node: --disable-warning= is not allowed in NODE_OPTIONS
```

### 原因
`--disable-warning=` 参数在 Node 16 中不允许。

### 解决方案
```bash
# 临时清除 NODE_OPTIONS
unset NODE_OPTIONS

# 或者修改为允许的参数
export NODE_OPTIONS="--max-old-space-size=4096"
```

### 永久修复
```bash
# 编辑 shell 配置文件
nano ~/.zshrc

# 找到包含 NODE_OPTIONS 的行，删除或注释掉
# 然后重新加载配置
source ~/.zshrc
```

## 12. Telegram 通道 Invalid URL 错误

### 问题
```
error gateway/channels/telegram [default] channel exited: Invalid URL
error gateway request handler failed: TypeError: Invalid URL: code=ERR_INVALID_URL
```

### 详细错误
```
Error: InvalidArgumentError: Invalid URL protocol: URL must start with `http:` or `https:`
```

### 原因
Telegram 配置中某个 URL 格式不正确，没有以 `http:` 或 `https:` 开头。

### 常见错误配置
```json
// ❌ 错误 - 缺少协议
{
  "telegram": {
    "webhookUrl": "example.com/webhook",
    "proxy": "127.0.0.1:1080"
  }
}

// ❌ 错误 - 不支持的协议
{
  "telegram": {
    "proxy": "socks5://127.0.0.1:1080"
  }
}

// ✅ 正确
{
  "telegram": {
    "webhookUrl": "https://example.com/webhook",
    "proxy": "http://127.0.0.1:1080"
  }
}
```

### 解决方案

#### 方式 1：禁用 webhook 和 proxy（最简单）
```bash
nano ~/.clawdbot/moltbot.json
```

修改配置：
```json
{
  "telegram": {
    "webhookUrl": null,
    "webhookSecret": null,
    "webhookPath": null,
    "proxy": null
  }
}
```

#### 方式 2：修正 URL 格式
确保 URL 格式正确：
- Webhook: `"webhookUrl": "https://your-domain.com/webhook"`
- Proxy: `"proxy": "http://127.0.0.1:1080"`（注意：必须是 http://，不能是 socks5://）

#### 检查配置
```bash
# 查看 Telegram 配置
cat ~/.clawdbot/moltbot.json | jq '.telegram'
```

#### 重启网关
```bash
pnpm moltbot gateway restart
```

## 13. nvm 更改默认 Node 版本

### 问题
如何使用 nvm 设置电脑终端的默认 Node 版本，避免每次打开新终端都需要手动切换。

### 解决方案

#### 1. 查看已安装的 Node 版本
```bash
nvm list
```

#### 2. 设置默认版本
```bash
# 设置为默认版本
nvm alias default 22

# 或者直接使用特定版本
nvm alias default 22.22.0
```

#### 3. 验证默认版本
```bash
# 查看默认别名
nvm alias

# 打开新终端验证
node -v
```

#### 4. 如果没有安装目标版本
```bash
# 先安装
nvm install 22

# 然后设置为默认
nvm alias default 22
```

#### 5. 临时切换版本（当前会话）
```bash
# 切换到其他版本（仅当前会话）
nvm use 16
```

#### 6. 卸载不需要的版本
```bash
# 卸载指定版本
nvm uninstall 16.20.2
```

### 完整示例
```bash
# 1. 查看所有版本
nvm list

# 2. 安装 Node 22（如果未安装）
nvm install 22

# 3. 设置为默认版本
nvm alias default 22

# 4. 验证
nvm alias
node -v
```

### 注意事项
- 设置默认版本后，新打开的终端会自动使用该版本
- 当前终端需要执行 `nvm use 22` 才能立即切换
- 可以使用 `nvm alias` 查看所有别名设置
- Clawdbot 项目要求 Node >=22.12.0
